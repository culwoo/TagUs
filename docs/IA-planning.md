# TagUs IA (User/Planner View)

- 작성일: 2026-02-06
- 관점: 기술 구조가 아닌 사용자 목표/행동 중심 IA

## 1. IA Goal

TagUs의 IA 목적은 아래 3가지를 가장 짧은 동선으로 지원하는 것이다.

1. 물건을 빠르게 등록한다.
2. 물건 상태와 위치를 계속 최신으로 유지한다.
3. 필요 시 알림/채팅으로 후속 행동을 이어간다.

## 2. Top-Level Structure

| Level 1 | Level 2 | 사용자 질문 | 핵심 행동 |
|---|---|---|---|
| 진입 | 로그인 | "바로 시작할 수 있나?" | Google 로그인 |
| 홈 | 내 물건/메모/알림 진입 | "지금 내 물건 상태가 어떤가?" | 물건 확인, 메모 작성, 알림 열기 |
| 전역 액션 | 물건 등록 플로우 | "새 물건을 어떻게 등록하지?" | 사진 선택, 이름 입력, 등록 완료 |
| 위치 관리 | 상태/위치 편집 | "이 물건을 어디에 두었지?" | 상태 변경, 위치 저장 |
| 채팅 | 대화 목록/준비 상태 | "찾는 사람과 소통할 수 있나?" | 대화 확인, 후속 대화 |
| 프로필 | 계정 정보/로그아웃 | "내 계정 상태는?" | 계정 확인, 로그아웃 |
| 전역 오버레이 | 알림 센터 | "최근 변경사항이 뭐지?" | 읽음 처리, 삭제 |

## 3. Navigation Model

| 네비게이션 타입 | 항목 | IA 원칙 |
|---|---|---|
| 하단 탭(1차) | 홈 / 채팅 / 위치관리 / 프로필 | 기능군이 아니라 사용자 목적군으로 라벨링 |
| 전역 CTA | `+ 물건 등록` | 어떤 탭에서도 즉시 실행 가능해야 함 |
| 전역 유틸 | 알림 센터 | 홈 헤더에서 열리지만 서비스 전역 이벤트를 보여줌 |

## 4. IA Map (Planning)

```text
TagUs
├─ 진입
│  └─ 로그인 (Google)
├─ 홈
│  ├─ 현재 선택 물건 요약 (위치/역/보관함)
│  ├─ 물건 목록(캐러셀)
│  │  ├─ 이름 수정
│  │  └─ 삭제
│  ├─ 개인 메모
│  └─ 알림 센터 열기
├─ 물건 등록 (전역 + 버튼)
│  ├─ 사진 선택/촬영
│  ├─ 물건명 입력
│  ├─ 원본 등록
│  └─ 배경 제거 후 등록
├─ 위치 관리
│  ├─ 물건 선택
│  ├─ 상태 변경 (보관중/분실/찾음)
│  └─ 위치 정보 저장 (장소/역/보관함)
├─ 채팅
│  └─ 대화 목록 (준비/진행)
└─ 프로필
   ├─ 계정 정보 확인
   └─ 로그아웃
```

## 5. Key User Flows

### Flow A: 신규 물건 등록

로그인 -> 홈 -> `+ 물건 등록` -> 사진 선택 -> 이름 입력 -> 등록 완료 -> 홈에서 확인

### Flow B: 위치/상태 갱신

홈(또는 탭 전환) -> 위치 관리 -> 물건 선택 -> 상태/위치 수정 -> 저장 -> 알림 확인

### Flow C: 일상 점검 루프

홈 진입 -> 내 물건/최근 위치 확인 -> 메모 업데이트 -> 알림 정리 -> 종료

## 6. Screen-Level Information Priority

| 화면 | 상단(먼저 보여줄 정보) | 중단(핵심 작업) | 하단(보조 작업) |
|---|---|---|---|
| 홈 | 현재 선택 물건의 위치 요약 | 물건 목록 탐색/편집 | 메모, 알림 진입 |
| 물건 등록 | 사진 미리보기/등록 단계 | 이름 입력, 등록 옵션 선택 | 에러/안내 메시지 |
| 위치 관리 | 현재 선택 물건 + 현재 상태 | 상태 변경, 위치 입력/저장 | 슬라이드 인디케이터 |
| 채팅 | 대화 상태(준비/최근) | 대화방 목록 확인 | 업데이트 시각 |
| 프로필 | 사용자 이름/이메일 | 로그아웃 | 보조 안내 텍스트 |
| 알림 센터 | 최신 알림 | 읽음/삭제 액션 | 전체삭제/닫기 |

## 8. IA Decision Rules

1. 탭은 "자주 반복되는 목적"만 둔다.
2. 등록은 탭이 아닌 전역 CTA로 유지한다.
3. 알림/확인/삭제 같은 보조 태스크는 오버레이로 분리한다.
4. 빈 상태(등록 물건 없음, 채팅 없음)도 정식 IA 노드로 간주한다.
5. 사용자 언어를 우선하고, 내부 구현 용어는 문서에서 배제한다.

## 9. Scope Notes

- 현재 IA는 개인 사용자 단일 역할 기준이다.
- 추후 역할(예: 관리자, 파트너 센터)이 추가되면 `역할별 IA`를 분리한다.
- 채팅이 실제 상호작용 단계로 확장되면 `채팅 상세`를 Level 2에 독립 추가한다.
